# Hardening release validation

This is the release gate for the pre-switch hardening change. Every live case below is **not yet run** unless an evidence record names the exact source revision, MSI hash, Windows build/architecture, VM snapshot, result, and supporting files. Source tests and packaging checks do not establish packet behavior.

Use a disposable Windows VM with working local/virtual console, a clean snapshot, and a second VM for inbound probes. Never exercise service termination, policy fault injection, audit changes, or installation on the development host. Build all Release MSIs, then prepare the bundle using `tools/vm/Prepare-SecureWallVmBundle.ps1`. Its guarded runner covers only the basic fresh-install path through the actual MSI.

| Case | Required result and evidence |
|---|---|
| Fresh MSI, full UI and silent | Own deny filters commit before compatibility allows; unknown TCP/UDP remain blocked; capture MSI log, WFP state and external probes |
| Normal prompts over IPv4/IPv6 | Only eligible outbound drops prompt; runtime filter IDs are promptable; Allow creates only permanent subject-wide outbound TCP/UDP access; Ignore/close/expiry change no policy |
| Save, registration and commit failures | Request reports failure; no false state/success display; prior policy remains coherent or a visible blocked/degraded state results; explicit deny never silently disappears |
| Expiring grant plus storage/registration failure | At the expiry maintenance pass, any snapshot/save/enforcement failure withdraws the dynamic session; traffic cannot retain the expired permission through repeated failures |
| Recovery failure with active event subscription | Native session close completes before compatibility cleanup; retained SafeHandle references cannot leave candidate grants active |
| Malformed explicit block address | Rule construction fails the replacement transaction, including mixed valid/invalid lists; a valid opposite-family address alone may be skipped for the other address family |
| BlockAll with LAN and WSL_2 enabled | Both inbound and outbound LAN/WSL traffic remain denied through supported paths; no higher-priority optional permit |
| Service stop/crash, startup failure and BFE restart | Runtime allowances disappear; persistent deny baseline remains; saved settings restore only after successful service start; no temporary allow on next boot |
| Cold boot/fast startup from every mode | Disabled/Learning and timed/until-reboot grants never become persistent permissive policy; measure early outbound and inbound traffic |
| Password inactivity | Unlock, leave tray polling for eleven minutes, confirm relock; background activity cannot refresh the user-activity deadline |
| Counterfeit pipe and multi-user sessions | Wrong process/token/service PID rejected before credentials; real SYSTEM service works; prompt tokens remain service-owned, bounded, and single use |
| Paused popup/backlog | AI expansion, service restart, repeated drops and multiple controllers cannot keep expired or absent tokens actionable or grow an unbounded display queue |
| TinyWall coexistence | MSI, direct install, elevated controller recovery and service entry refuse activation before mutation when TinyWall exists |
| Unsafe payload tree | Downloads, writable Program Files subdirectories, writable DLL/config files, untrusted owners and reparse paths are rejected before service registration |
| Fresh install rollback at each stage | No leftover service/task/provider/compatibility allowances; restore original notifications, audit and hosts state; no inaccessible UI or password dialog |
| Startup stuck beyond its advertised deadline | Failed-install SYSTEM rollback disables restart and attempts bounded graceful cleanup, then can terminate only the validated held service process; no PID-reuse victim or running service survives payload rollback |
| Explicit MSI removal, unlocked and password locked | Privileged MSI cleanup remains noninteractive; ordinary interactive recovery retains its confirmation path; failure returns nonzero |
| Unresponsive service during ordinary removal | Bounded stop fails before protection or files are removed; preserve logs and recover via snapshot/local console |
| Uninstall after abrupt exit | Restore owned compatibility state even with service stopped; remove own deny baseline only after fallback restoration succeeds |
| MpsSvc stopped or disabled | Fresh installation rejects an unavailable prerequisite before registration; dependency ordering starts MpsSvc at boot; removal skips COM only with no recorded compatibility state; recorded restoration failure retains deny baseline |
| Slow service disposal | SCM stays stop-pending through late cleanup; within the bounded deadline it reaches stopped, otherwise the process exits and runtime grants disappear; no running state with a disposed worker |
| Process exits during failed-install rollback | A failed process open triggers a fresh SCM status check; cleanup continues only when stopped and restoration succeeds |
| Held service handle during removal | Completed cleanup accepts checked deferred deletion; fresh install remains refused until handles close or reboot removes the old registration |
| Corrupt config.recovery | Startup fails closed; preserve evidence and restore a known-good backup or perform full MSI removal/reinstall from the local console |
| Repair, equal-version rebuild and upgrade attempts | Unsupported operations reject before any teardown; existing service, files and effective policy remain unchanged |
| Mixed notification settings and colliding rule name | Restore each original profile value; preserve unrelated rules whose names contain SecureWall; a foreign reserved-name rule alone rejects compatibility acquisition before notification/rule mutation; inspect durable journal cleanup |
| Malicious precreated machine data | Before MSI install, precreate the data directory with an ordinary-user owner/write ACE, then separately a junction root, junction ancestor and unsafe nested file. Install rejects before seeding, logging, service registration or policy reads/writes; compare attack-tree and junction-target hashes/ACLs before and after. Repeat with a creation race; do not repair the hostile tree during the test |
| Protected defaults and preserved data | Inspect the built MSI tables: both defaults target INSTALLDIR/data-defaults, with no ProgramData file/removal components. Fresh SYSTEM install creates protected machine data and copies both absent defaults; existing safe defaults remain byte-identical. Uninstall preserves machine-data evidence |
| Controller starts during policy replacement | Repeatedly launch an ordinary-user installed Release controller while the service replaces a same-directory temporary configuration file. A disappearing child under a revalidated safe parent does not prevent startup. Unsafe parent replacement, inaccessible child or missing root still rejects; no unprivileged machine-data writes |
| Corrupt active configuration | Test truncated encrypted data, invalid JSON, decryption failure and read denial separately with no recovery journal. Startup fails closed and preserves evidence; only confirmed absence selects defaults. Repeat with a valid journal and verify prior-policy recovery before active-config loading |
| Candidate write fails after swap | Inject failure in the installed-file flush after candidate replacement. Request returns failure and attempts prior-policy compensation even though save did not return successfully. Retry with compensation failure and journal-clear failure after WFP commit: runtime grants disappear, no false success is published, and recovery evidence is retained or re-established |
| Required display/network reload fails | Trigger a display power transition and an address/interface change while injecting rule registration failure. Dynamic grants are withdrawn; UI reports failure/degradation and prior published state does not falsely describe a successful replacement |
| Queue saturation and expiry | Flood distinct eligible identities beyond service/candidate/display limits, pause a popup past its absolute deadline, and keep tray polling past the password timeout. Memory and diagnostics stay bounded; suppressed/expired entries remain blocked, stale Allow is rejected, and worker-side locking does not deadlock on its own full queue |
| Child-process identity | Allow a parent that starts a distinct blocked child; the child needs its own authority. Exercise incremental inherited/raw-socket rules and full reload using DOS and native paths. Compare installed application identities and verify no parent/sibling or unrelated service receives a broader grant |
| Hosts restoration failure | Enable hosts protection, then deny backup reads or target replacement and inject a post-swap failure. Settings/removal returns failure before service deletion, preserving the original backup on failed restore. Restore access and verify exact original bytes. A genuinely absent original backup with protection never enabled remains a successful no-op |
| Batched service attribution | Burst exact-correlated drops, then change shared-service membership before the next batch. Verify one fresh SCM snapshot per drained batch, no cross-batch identity reuse, non-allowable shared hosts, visible capacity/contention/deadline suppression, and no actionable tokens after policy change or shutdown. Exercise a callback waiting on learning while disposal drains and policy transitions run; confirm bounded service stop. |
| Audit loss and suppression | Interrupt the 5157 subscription, deny event access and saturate correlation buffers separately. Verify degraded controller notification and coalesced counters without a log flood; ambiguous services remain non-allowable. Restore access, confirm attribution stays unavailable until service restart, then observe health recovery without weakening WFP or changing original audit-lease recovery expectations |
| File and parent mutation warnings | Use an executable with a writable file DACL or untrusted owner inside a protected directory, then a protected file inside a replaceable parent. Warning reflects each risk; signature/path text never becomes content-pinned authority |
| Windows Update service isolation | With the default Windows_Update profile enabled, inspect the exact path plus wuauserv filter and absence of executable-wide svchost web permits. Exercise scan/download/install/reboot. An unrelated service in svchost cannot use this profile to reach TCP 80/443; record additional required services as compatibility findings rather than adding a broad rule |
| Strict DNS/DHCP during boot and crash | Capture IPv4/IPv6 UDP/TCP DNS to port 53 and DHCPv4 67/68 plus DHCPv6 546/547 on an external peer across cold boot, fast startup, stopped service, abrupt termination and failed startup. All remain blocked while only the baseline is active; no recovery-port permits exist. Include hostile arbitrary DNS traffic and lease renewal; use the local console to recover |
| Startup, reconnect and IPv6 | Verify saved exact allows only return after successful startup. Repeat Wi-Fi/Ethernet reconnect, VPN reconnect, sleep/resume and IPv6-only/dual-stack address changes, including DHCPv6 and router discovery effects. Capture gaps and network recovery; startup blocking must not silently open traffic to recover connectivity |
| Other networking | DNS/DHCP changes, VPN reconnect, sleep/resume, ICMP/path-MTU, existing flow revocation, WSL NAT/mirrored networking, Hyper-V/containers and each supported CPU architecture |

Capture the complete before/after firewall rule inventory, profile notification values, audit policy, hosts hash, service configuration, scheduled tasks and WFP objects. The basic runner compares these for its happy path; crash and fault cases need separate captures. Any group-policy or unrelated administrator change during a run must be recorded rather than attributed automatically to SecureWall.

The AI feature must reject HTTP and redirects, disclose the actual transmitted identity fields, and label publisher information as unverified. Pure tests cover construction and validation; a local HTTPS test endpoint can verify transport/cancellation/response bounds without sending real user data or paid-provider credentials.

Signed production artifacts and an upstream/dependency maintenance process remain separate release requirements. No automatic update feed is introduced by this change. Preserve the exact build inputs and hash manifest, and monitor upstream/dependency fixes before adopting later releases.

## R9B source status and pending gates

Source inspection confirmed the nonadmin controller previously elevated `/install`, although that entry requires LocalSystem, and controller logging previously selected protected machine data. The bounded repair uses an existing validated service, start-only elevation, and bounded SCM Running observation. SYSTEM installation retains service creation. Pure regression cases now cover installation-context decisions, image/account/type rejection, lazy log destinations, denied machine storage without user fallback, and caller wiring. These new cases and application builds have not run; concurrent executors must stop before the manager releases shared verification.

The following VM cases remain unrun: standard-user and administrator controller repair; missing service without a UAC prompt; UAC cancellation; service start failure and timeout; StartPending and StopPending; pending deletion via registry and SCM error 1072; wrong image/account/type rejection; concurrent service start; user log creation; privileged log rejection without fallback; unsafe legacy data startup and MSI failure; clean TinyWall-only migration. Verify interactive diagnostics and absence of SYSTEM/session-0 UI. A controller can show a detailed failure followed by its caller's existing generic unavailable-service dialog; no controller-file edit was in this executor's scope.

Unsafe legacy trees remain rejected and untouched. The deferred MSI action still lacks a dedicated user-facing rejection dialog. Signing, package/ICE verification, the full WFP/hosts/audit/local-console matrix and physical power-loss durability remain pending. Source inspection establishes none of these runtime gates.
