# SecureWall v0.4.2

Website: https://secwall.org/

This is an unsigned alpha prerelease for exploratory testing. It stops blocked-connection prompts from disappearing before you answer them, and keeps the Network Activity list where you scrolled it. It is not signed or end-to-end verified. The changes below were checked with unit tests, builds, a synthetic popup check and code review; the tray list described below has not been tested on a live installation yet.

## Changes

### Prompts no longer disappear unanswered

On v0.4.1 a prompt could vanish without you seeing it, and the app then stayed blocked with no way back from the popup:

- The popup closed itself 30 seconds after it appeared, and that counted as Ignore, so the app got no new prompt for five minutes.
- Escape answered Ignore whenever the popup had keyboard focus, which it could take after you clicked an earlier popup. Space or Enter could press its focused button. Typing in another window could close a prompt.
- Only one popup shows at a time. A prompt waiting behind others expired after two minutes, and allowing one app cancelled every other waiting prompt. An app that tries to connect only once got no second prompt.

Now:

- The popup stays until you click Allow, Ignore or close, or until its two-minute token expires. Leaving it alone does not mute the app.
- The popup never takes keyboard focus, so keystrokes meant for other windows cannot answer or close it. Only mouse clicks can.
- The popup title shows how many more prompts are waiting, for example "(+2 waiting)".
- A prompt that leaves without an answer (expired, or cancelled when you allowed another app) is listed in the tray menu under **Blocked apps not answered**, and a notification names the app. Click an entry, or the notification, to allow it. SecureWall asks you to confirm, asks for the password when the firewall is locked, and saves the same outgoing-only rule as Allow in the popup. If the app tries again and a new prompt appears, its entry leaves the list. The list holds the 20 most recent entries and is cleared when the tray app exits.

Ignore still mutes that one app for five minutes. Prompt tokens still expire after two minutes and are still revoked by every policy change; the list only remembers which apps were blocked.

### Network Activity

The list refreshes every second, and each refresh used to jump back to the top and clear your selection. It now keeps the row you were looking at and your selection. If you are at the top, it stays at the top so new entries remain visible.

## Downloads and installation

Use `SecureWall_x64.msi` on Intel/AMD 64-bit Windows, `SecureWall_arm64.msi` on Windows on ARM, or `SecureWall_x86.msi` on 32-bit Windows. Verify the download against `SHA256SUMS.txt`. All installers are unsigned. Keep local console access and recovery installers available offline. Service loss can leave external networking blocked, including DNS and DHCP.

**Upgrading.** In-place upgrades and repair are still unsupported. If an earlier SecureWall is installed, remove it from Settings > Apps at the local console, then install v0.4.2. The existing `%ProgramData%\SecureWall` folder, including your rules, is reused if it passes validation. If v0.3.0 is installed, read the upgrade notes in [v0.4.0](v0.4.0.md#downloads-and-installation) first.

**Switching from TinyWall.** Follow [before switching](../LIVE-TESTING.md#before-switching) first. Uninstall TinyWall with its own uninstaller and reboot before installing SecureWall; setup refuses to run while TinyWall or its firewall provider is still registered. To go back to TinyWall later, uninstall SecureWall first and follow [rolling back to TinyWall](../LIVE-TESTING.md#rolling-back-to-tinywall).

## Collect a diagnostic report

Read [the live testing guide](../LIVE-TESTING.md) and [coverage map](../DIAGNOSTIC-COVERAGE.md). Download the source archive for this tag to obtain `tools/diagnostics`, or use a checkout of this tag. Run the collector with Windows PowerShell 5.1 as described in [its README](../../tools/diagnostics/README.md). It creates a local report and does not upload it.

Logs record software outcomes and observed filtering decisions. They do not prove packet delivery, absence of boot/crash leakage, installer rollback, hostile filesystem resistance or power-loss durability. The bundled blocklists do not automatically update. Review normal-use logs before drawing conclusions about live behavior.
