# SecureWall v0.4.2

Website: https://secwall.org/

This is an unsigned alpha prerelease for exploratory testing. Blocked-connection prompts no longer close on their own after 30 seconds or from stray keys, and a prompt that leaves unanswered is listed in the tray menu. Apps signed by a publisher you trust can be allowed in every new folder they update into, and Network Activity and Manage can be open at the same time. It is not signed or end-to-end verified. The changes below were checked with unit tests, builds, synthetic popup checks and code review only; none of them has been tested on a live installation yet.

## Changes

### Prompts no longer disappear unanswered

On v0.4.1 a prompt could vanish without you seeing it, and the app then stayed blocked with no way back from the popup:

- The popup closed itself 30 seconds after it appeared, and that counted as Ignore, so the app got no new prompt for five minutes.
- Escape answered Ignore whenever the popup had keyboard focus, which it could take after you clicked an earlier popup. Space or Enter could press its focused button, so typing in another window could close a prompt.
- Only one popup shows at a time. A prompt waiting behind others expired after two minutes, and any policy change, such as allowing another app, cancelled every waiting prompt. An app that tries to connect only once got no second prompt.

Now:

- The popup stays until you click Allow, Ignore or close, or until its token expires (two minutes after the connection was blocked, not after the popup appears) or a policy change cancels it. Leaving it alone does not mute the app.
- The popup never takes keyboard focus, even when you click it while another SecureWall window is in front, so keys typed into other windows cannot answer or close it. You answer it by clicking. Other programs running as you can still press its buttons. With a password set and SecureWall locked, they cannot allow anything without you: their Allow opens the password dialog, so type the password only for a prompt you recognize. They can still press Ignore.
- The popup title shows how many more prompts are waiting, for example "(+2 waiting)".
- A prompt that leaves without an answer is listed in the tray menu under **Blocked apps not answered**, and a notification names the app (or gives a count when several leave at once). Each app entry offers Allow and Always allow (Always allow works only for a file with a valid embedded signature on a local drive; otherwise it explains why); clicking a single-app notification offers Allow. SecureWall asks you to confirm, opens the exception editor next if you turned it on in Manage, asks for the password when the firewall is locked and locks it again afterwards, and saves the same outgoing-only rule as Allow in the popup. Entries SecureWall cannot allow, such as a shared Windows service host, are listed too; hover to see why, and choosing Allow explains it. If the app tries again and a new prompt appears, its entry leaves the list. The list holds the 20 most recent entries and is cleared when the tray app exits.
- A brief loss of contact with the service no longer closes the popup.

Ignore, or closing the popup, still mutes that one app for five minutes. Prompt tokens still expire after two minutes, and policy changes still cancel them.

### Always allow

Apps such as Claude install each update into a new folder (`AnthropicClaude\app-<version>\claude.exe`), so an allow rule for the old path stops working and the app is blocked again. **Always allow** fixes that for signed apps:

- It appears in the popup next to Allow, and in the **Blocked apps not answered** list. In the popup it stays only for a file with a valid embedded signature on a local fixed drive, in a folder with no symbolic links, junctions or OneDrive placeholders; its tooltip names the publisher.
- It allows this copy now and saves a rule: this file name, signed by this publisher, in any folder. When a later copy with that name is blocked, SecureWall checks its signature and, if the publisher matches exactly, adds the same outgoing-only rule as Allow for that copy's exact path without prompting. Connections from a new copy fail until that rule is in place, usually just the first one; an app that does not retry stays offline until you restart it. Adding the rule is a policy change, so any prompts on screen at that moment move to **Blocked apps not answered**.
- You are prompted as usual for a file with the same name but no valid signature or a signature from anyone else; for a copy on a network share, a removable drive, or behind a link or cloud placeholder; and for a copy you already have a rule for, so a rule you limited to some ports is never widened.
- The rule trusts the publisher: any file with that name and that publisher's signature is allowed from any folder. Use it only for publishers you trust. SecureWall checks certificate revocation only against data Windows already has cached, so a publisher certificate that was revoked after theft can still be accepted.
- Like every allow rule, the rule SecureWall adds follows the file's path, not its contents. A program already running as you could copy a signed app into its own folder, run it so SecureWall allows that file's path, and then put its own program in its place. Replacing an app you already allowed works the same way today. The SecureWall password does not stop either case.
- Manage has a new **Always allow** tab that lists the rules; Remove stops future automatic allows. Rules already added for exact paths stay in the application list until you remove them there.

### Network Activity and Manage

- Network Activity and Manage can now be open at the same time, as separate windows.
- If the firewall settings change while Manage is open (you allow or unblock something, switch mode, a timed rule expires, or Always allow adds a rule by itself), Manage's next OK is refused with "make your changes again" instead of overwriting the new rule. When that happens nothing from Manage is applied, including a password or language change.
- Network Activity refreshes every second, and each refresh used to jump back to the top and clear your selection. It now keeps the row you were looking at and your selection. If you are at the top, it stays at the top so new entries remain visible.

## Downloads and installation

Use `SecureWall_x64.msi` on Intel/AMD 64-bit Windows, `SecureWall_arm64.msi` on Windows on ARM, or `SecureWall_x86.msi` on 32-bit Windows. Verify the download against `SHA256SUMS.txt`. All installers are unsigned. Keep local console access and recovery installers available offline. Service loss can leave external networking blocked, including DNS and DHCP.

**Upgrading.** In-place upgrades and repair are still unsupported. Download and verify the v0.4.2 installer first. Optionally export your settings (Manage, Maintenance tab, **Export Settings**; the export does not include the password) as a backup. Then, at the local console, remove the earlier SecureWall from Settings > Apps and install v0.4.2.

- Between removal and reinstall SecureWall does not filter anything; Windows Defender Firewall's own settings apply.
- The existing `%ProgramData%\SecureWall` folder, including your rules and password, is reused if it passes validation.
- When setup finishes, the tray app looks for applications it knows (such as Chrome, Edge, Firefox, Google Update, SmartScreen and Steam) and adds allow rules for any it finds. The rules for Chrome, Firefox, Steam and WinSCP also accept incoming connections on any port. Where you already have a rule for the same file, the two are combined, so a rule you limited to some ports or to outgoing traffic is widened. If the firewall has a password, it asks for it first; cancel to skip all of this. If you don't cancel, check those applications in Manage afterwards and edit their ports back; deleting a combined rule also deletes your original one. After that password prompt SecureWall stays unlocked until you lock it from the tray menu or after 10 minutes of inactivity.
- If setup says SecureWall service deletion is pending, or that an existing SecureWall service must be removed, close Services and other service-management tools or restart Windows, then try again.
- If removal fails, stop. The earlier SecureWall stays installed, and external traffic may stay blocked. Keep `%ProgramData%\SecureWall` as it is and see [operational safety](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/docs/SECURITY.md#operational-safety) and the [live testing guide](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/docs/LIVE-TESTING.md#if-the-trial-breaks-networking).
- If v0.4.2 setup fails, use **Open SecureWall log** and **Open setup log** on the failure page and keep both logs. Also check the Windows Application event log for Errors from source `SecureWall`. Event ID 1000 means the data folder was rejected; do not change its permissions. Event ID 1001 means a setup step (such as installing or starting the service) failed; its message and the logs name the step. See [failed first-install rollback](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/docs/SECURITY.md#failed-first-install-rollback) and [legacy data and controller recovery](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/docs/SECURITY.md#legacy-data-and-controller-recovery).
- If v0.3.0 is installed, read the upgrade notes in [v0.4.0](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/docs/releases/v0.4.0.md#downloads-and-installation) first.

**Switching from TinyWall.** Follow [before switching](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/docs/LIVE-TESTING.md#before-switching) first. Uninstall TinyWall with its own uninstaller and reboot before installing SecureWall; setup refuses to run while TinyWall or its firewall provider is still registered. To go back to TinyWall later, uninstall SecureWall first and follow [rolling back to TinyWall](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/docs/LIVE-TESTING.md#rolling-back-to-tinywall).

## Collect a diagnostic report

Read [the live testing guide](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/docs/LIVE-TESTING.md) and [coverage map](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/docs/DIAGNOSTIC-COVERAGE.md). Download the source archive for this tag to obtain `tools/diagnostics`, or use a checkout of this tag. Run the collector with Windows PowerShell 5.1 as described in [its README](https://github.com/ryanportfolio/SecureWall/blob/v0.4.2/tools/diagnostics/README.md). It creates a local report and does not upload it.

Logs record software outcomes and observed filtering decisions. They do not prove packet delivery, absence of boot/crash leakage, installer rollback, hostile filesystem resistance or power-loss durability. The bundled blocklists do not automatically update. Review normal-use logs before drawing conclusions about live behavior.
