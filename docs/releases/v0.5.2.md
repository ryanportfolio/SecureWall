# SecureWall v0.5.2

Website: https://secwall.org/

This is an unsigned alpha prerelease. SecureWall can now check GitHub for a newer release and install it, and the Network Activity list no longer moves while it refreshes.

## Changes

### Check for updates

- **Where.** **Check for updates** is in the tray menu and on the Maintenance tab in Manage. It runs only when you choose it; SecureWall never checks on its own. If SecureWall is locked, it asks for the password first.
- **Network access.** While a check or download runs, the service lets the installed `SecureWall.exe` running as you connect out on TCP port 443. The permission is never saved, lasts at most 10 minutes, and ends early when SecureWall locks. It is granted only in Normal mode, so the check does not work while SecureWall blocks all traffic or is in another mode.
- **What it offers.** It looks at the release list on GitHub and offers the newest release built for your architecture. Prereleases are included by default, since every SecureWall release is a prerelease for now; clear **Include prereleases** on the Maintenance tab to leave them out. A newer release whose installers are not attached yet is reported as not ready, not as up to date.
- **Install.** **Install** downloads the MSI and checks it against the release's `SHA256SUMS.txt`, whose header must name the same release and version. Windows then asks for administrator approval, SecureWall checks the installer again, and the usual in-place upgrade runs with its setup window. After the upgrade the tray shows "Updated to v<version>" once.
- **What it trusts.** The installers are not signed. The check trusts a release as far as it trusts the ryanportfolio/SecureWall GitHub account and HTTPS: anyone who can publish or replace release files there could supply an installer it offers. The hash check catches damaged or swapped downloads. [Check for updates](https://github.com/ryanportfolio/SecureWall/blob/v0.5.2/docs/SECURITY.md#check-for-updates) has the details.
- **From which version.** v0.5.2 is the first version with the button, and only releases from v0.5.2 on carry the release header it reads. Updating to v0.5.2 itself is still a manual install; the button can offer the release after it.

### Network Activity keeps its scroll position

- v0.5.1 still sent the list back to the top on each one-second refresh. Each refresh now updates the rows already in the list instead of rebuilding it, so the scrollbar stays where you left it. It moves only if the list gets shorter than your position. Live rows with the same timestamp keep their order between refreshes.

## Downloads and installation

Use `SecureWall_x64.msi` on Intel/AMD 64-bit Windows, `SecureWall_arm64.msi` on Windows on ARM, or `SecureWall_x86.msi` on 32-bit Windows. Verify the download against `SHA256SUMS.txt`. All installers are unsigned. Keep local console access and recovery installers available offline. Service loss can leave external networking blocked, including DNS and DHCP.

**Upgrading from v0.5.0 or v0.5.1.** Run the v0.5.2 installer for the same architecture at the computer's own keyboard and screen. It upgrades in place and keeps rules, settings and the password. While the service restarts, connections to other computers are blocked, usually for under a minute, and open connections drop; blocks in that window show as "Blocked" in Network Activity and are not prompted. Do not restart or power off the PC while setup runs. If a step fails, setup rolls back to the installed version; [In-place upgrade](https://github.com/ryanportfolio/SecureWall/blob/v0.5.2/docs/SECURITY.md#in-place-upgrade) has the recovery steps.

**Upgrading from v0.4.2 or older.** These versions cannot be upgraded in place. Uninstall SecureWall in Settings > Apps once, then install v0.5.2, following the one-time uninstall steps in the [v0.5.0 release notes](https://github.com/ryanportfolio/SecureWall/blob/v0.5.2/docs/releases/v0.5.0.md#downloads-and-installation).

**Switching from TinyWall.** Follow [before switching](https://github.com/ryanportfolio/SecureWall/blob/v0.5.2/docs/LIVE-TESTING.md#before-switching) first. Uninstall TinyWall with its own uninstaller and reboot before installing SecureWall; setup refuses to run while TinyWall or its firewall provider is still registered. To go back to TinyWall later, uninstall SecureWall first and follow [rolling back to TinyWall](https://github.com/ryanportfolio/SecureWall/blob/v0.5.2/docs/LIVE-TESTING.md#rolling-back-to-tinywall).

## Collect a diagnostic report

Read [the live testing guide](https://github.com/ryanportfolio/SecureWall/blob/v0.5.2/docs/LIVE-TESTING.md) and [coverage map](https://github.com/ryanportfolio/SecureWall/blob/v0.5.2/docs/DIAGNOSTIC-COVERAGE.md). Download the source archive for this tag to obtain `tools/diagnostics`, or use a checkout of this tag. Run the collector with Windows PowerShell 5.1 as described in [its README](https://github.com/ryanportfolio/SecureWall/blob/v0.5.2/tools/diagnostics/README.md). It creates a local report and does not upload it.

Logs record software outcomes and observed filtering decisions. They do not prove packet delivery, absence of boot/crash leakage, installer rollback, hostile filesystem resistance or power-loss durability. The bundled blocklists do not automatically update. Review normal-use logs before drawing conclusions about live behavior.
