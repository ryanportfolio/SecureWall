# SecureWall v0.5.3

Website: https://secwall.org/

This is an unsigned alpha prerelease. AI help's **?** lookup now works on systems where an older rule blocked SecureWall without the user knowing, its switch has a place in Manage, and a failed lookup says why.

## Changes

### AI help

- **Blocks no longer stop it.** A block on `services.exe` with "child processes inherit" turned on also blocks the SecureWall service, and with it `SecureWall.exe`, which the tray app shares. Such a rule never shows in the exception list, and it made every lookup fail with "An error occurred while sending the request." AI help's network permit now ranks above user blocks, so turning AI help on is enough. Blocklists still take precedence. To stop AI help's network access, turn the setting off. Check for updates uses the same ranking.
- **Where to turn it on.** Manage > Special Exceptions > Optional has a new **SecureWall AI help** row, off by default. It is the same setting the popup's **?** button turns on; SecureWall must be unlocked to change it. The permit still allows only outbound TCP port 443 for `SecureWall.exe` running in a signed-in account, never the SecureWall service.
- **Failed lookups say why.** The popup names the likely cause and what to do: AI help's network access is off, the firewall is in Block all mode, the AI service's name could not be found, or the secure connection or the connection itself failed. The underlying error follows, with the socket error number when there is one.
- **The SecureWall.exe exception warning points at the switch.** Adding an exception for `SecureWall.exe` still warns that the rule would also open the SecureWall service, and now tells you where the AI help row is instead.

The [security model](https://github.com/ryanportfolio/SecureWall/blob/v0.5.3/docs/SECURITY.md) describes the permit in its paragraphs on optional AI explanations.

## Downloads and installation

Use `SecureWall_x64.msi` on Intel/AMD 64-bit Windows, `SecureWall_arm64.msi` on Windows on ARM, or `SecureWall_x86.msi` on 32-bit Windows. Verify the download against `SHA256SUMS.txt`. All installers are unsigned. Keep local console access and recovery installers available offline. Service loss can leave external networking blocked, including DNS and DHCP.

**Upgrading from v0.5.2.** Choose **Check for updates** in the tray menu or on the Maintenance tab in Manage, then **Install**.

**Upgrading from v0.5.0, v0.5.1 or v0.5.2 by hand.** Run the v0.5.3 installer for the same architecture at the computer's own keyboard and screen. It upgrades in place and keeps rules, settings and the password. While the service restarts, connections to other computers are blocked, usually for under a minute, and open connections drop; blocks in that window show as "Blocked" in Network Activity and are not prompted. Do not restart or power off the PC while setup runs. If a step fails, setup rolls back to the installed version; [In-place upgrade](https://github.com/ryanportfolio/SecureWall/blob/v0.5.3/docs/SECURITY.md#in-place-upgrade) has the recovery steps.

**Upgrading from v0.4.2 or older.** These versions cannot be upgraded in place. Uninstall SecureWall in Settings > Apps once, then install v0.5.3, following the one-time uninstall steps in the [v0.5.0 release notes](https://github.com/ryanportfolio/SecureWall/blob/v0.5.3/docs/releases/v0.5.0.md#downloads-and-installation).

**Switching from TinyWall.** Follow [before switching](https://github.com/ryanportfolio/SecureWall/blob/v0.5.3/docs/LIVE-TESTING.md#before-switching) first. Uninstall TinyWall with its own uninstaller and reboot before installing SecureWall; setup refuses to run while TinyWall or its firewall provider is still registered. To go back to TinyWall later, uninstall SecureWall first and follow [rolling back to TinyWall](https://github.com/ryanportfolio/SecureWall/blob/v0.5.3/docs/LIVE-TESTING.md#rolling-back-to-tinywall).

## Collect a diagnostic report

Read [the live testing guide](https://github.com/ryanportfolio/SecureWall/blob/v0.5.3/docs/LIVE-TESTING.md) and [coverage map](https://github.com/ryanportfolio/SecureWall/blob/v0.5.3/docs/DIAGNOSTIC-COVERAGE.md). Download the source archive for this tag to obtain `tools/diagnostics`, or use a checkout of this tag. Run the collector with Windows PowerShell 5.1 as described in [its README](https://github.com/ryanportfolio/SecureWall/blob/v0.5.3/tools/diagnostics/README.md). It creates a local report and does not upload it.

Logs record software outcomes and observed filtering decisions. They do not prove packet delivery, absence of boot/crash leakage, installer rollback, hostile filesystem resistance or power-loss durability. The bundled blocklists do not automatically update. Review normal-use logs before drawing conclusions about live behavior.
