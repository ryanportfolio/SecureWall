# SecureWall v0.5.4

Website: https://secwall.org/

This is an unsigned alpha prerelease. An app's own rule now outranks rules it would otherwise inherit from a parent process, so an allowed app such as the Microsoft Store is no longer blocked by an "apply to child processes" block on a system process further up the chain.

## Changes

### Child-process rules

- **An app's own rule wins.** A process whose executable or app package (UWP app) has a rule in Application Exceptions no longer inherits rules from its parent processes. Before, only an executable rule protected a process; a package rule did not. Some profiles imported from TinyWall block `services.exe` with "Apply same rules to child processes" turned on. On those PCs, the Microsoft Store and other apps Windows starts through `svchost.exe` were blocked even with an allow rule for their package.
- **Inheritance stops at a ruled parent.** When SecureWall looks up the parent chain for a rule to inherit, it now stops at the first parent that has its own rule for the whole executable or package and does not pass that rule on. Rules from parents further up no longer reach the processes below it. A rule for a single Windows service does not stop the lookup, because it covers one service and not every `svchost.exe`. Processes with no ruled parent in between still inherit as before, so a block on a system process still applies to its children that have no rule of their own.
- **Path case no longer matters.** An inherited rule now applies whatever the letter case of its path compared with the path Windows reports for the running parent, for example `c:\tools\app.exe` against `C:\Tools\App.exe`. Before, a case difference made the rule stop applying to children. Inherited blocks that silently did nothing because of this now take effect.

## Downloads and installation

Use `SecureWall_x64.msi` on Intel/AMD 64-bit Windows, `SecureWall_arm64.msi` on Windows on ARM, or `SecureWall_x86.msi` on 32-bit Windows. Verify the download against `SHA256SUMS.txt`. All installers are unsigned. Keep local console access and recovery installers available offline. Service loss can leave external networking blocked, including DNS and DHCP.

**Upgrading from v0.5.2 or v0.5.3.** Choose **Check for updates** in the tray menu or on the Maintenance tab in Manage, then **Install**.

**Upgrading from v0.5.0, v0.5.1, v0.5.2 or v0.5.3 by hand.** Run the v0.5.4 installer for the same architecture at the computer's own keyboard and screen. It upgrades in place and keeps rules, settings and the password. While the service restarts, connections to other computers are blocked, usually for under a minute, and open connections drop; blocks in that window show as "Blocked" in Network Activity and are not prompted. Do not restart or power off the PC while setup runs. If a step fails, setup rolls back to the installed version; [In-place upgrade](https://github.com/ryanportfolio/SecureWall/blob/v0.5.4/docs/SECURITY.md#in-place-upgrade) has the recovery steps.

**Upgrading from v0.4.2 or older.** These versions cannot be upgraded in place. Uninstall SecureWall in Settings > Apps once, then install v0.5.4, following the one-time uninstall steps in the [v0.5.0 release notes](https://github.com/ryanportfolio/SecureWall/blob/v0.5.4/docs/releases/v0.5.0.md#downloads-and-installation).

**Switching from TinyWall.** Follow [before switching](https://github.com/ryanportfolio/SecureWall/blob/v0.5.4/docs/LIVE-TESTING.md#before-switching) first. Uninstall TinyWall with its own uninstaller and reboot before installing SecureWall; setup refuses to run while TinyWall or its firewall provider is still registered. To go back to TinyWall later, uninstall SecureWall first and follow [rolling back to TinyWall](https://github.com/ryanportfolio/SecureWall/blob/v0.5.4/docs/LIVE-TESTING.md#rolling-back-to-tinywall).

## Collect a diagnostic report

Read [the live testing guide](https://github.com/ryanportfolio/SecureWall/blob/v0.5.4/docs/LIVE-TESTING.md) and [coverage map](https://github.com/ryanportfolio/SecureWall/blob/v0.5.4/docs/DIAGNOSTIC-COVERAGE.md). Download the source archive for this tag to obtain `tools/diagnostics`, or use a checkout of this tag. Run the collector with Windows PowerShell 5.1 as described in [its README](https://github.com/ryanportfolio/SecureWall/blob/v0.5.4/tools/diagnostics/README.md). It creates a local report and does not upload it.

Logs record software outcomes and observed filtering decisions. They do not prove packet delivery, absence of boot/crash leakage, installer rollback, hostile filesystem resistance or power-loss durability. The bundled blocklists do not automatically update. Review normal-use logs before drawing conclusions about live behavior.
