# SecureWall v0.5.5

Website: https://secwall.org/

This is an unsigned alpha prerelease. Updates installed with **Check for updates** no longer stop on setup's "Files in Use" page because a SecureWall window is still open.

## Changes

### Check for updates

- **Manage and Network Activity close when setup starts.** After you approve the administrator prompt, SecureWall closes Manage and Network Activity before setup's window appears. Changes not yet applied in Manage are discarded, as Cancel does, so apply or cancel them before you click **Install**. The update window says so. Before, an open Manage window made setup stop on its "Files in Use" page, which listed "SecureWall Firewall Settings".
- **Other windows are closed first.** If another SecureWall window is open when you click **Install**, or opens while the installer downloads, such as a message box, the file picker or the exception editor, SecureWall asks you to close it and click **Install** again.
- **The tray waits for setup.** While setup runs, the tray menu, a middle click on the tray icon, a click on a notification, and a prompt's password and AI assistant requests open nothing; a notification says setup is running. They work again once setup finishes or you cancel it, or when the update step refuses to install. Another installer running on your session at the same time keeps the tray waiting until that installer ends too.
- **Include prereleases is kept.** If you changed **Include prereleases** on Manage's Maintenance tab and checked for updates without applying, the choice is saved when setup starts, instead of being discarded with Manage's other changes.

These changes take effect for updates started from v0.5.5. Updating to v0.5.5 still runs the installed version's updater, which leaves those windows open. If setup stops on its "Files in Use" page and lists a SecureWall window, choose **Ignore**: setup closes SecureWall itself before it replaces any file.

## Downloads and installation

Use `SecureWall_x64.msi` on Intel/AMD 64-bit Windows, `SecureWall_arm64.msi` on Windows on ARM, or `SecureWall_x86.msi` on 32-bit Windows. Verify the download against `SHA256SUMS.txt`. All installers are unsigned. Keep local console access and recovery installers available offline. Service loss can leave external networking blocked, including DNS and DHCP.

**Upgrading from v0.5.2, v0.5.3 or v0.5.4.** Choose **Check for updates** in the tray menu or on the Maintenance tab in Manage, then **Install**.

**Upgrading from v0.5.0 through v0.5.4 by hand.** Run the v0.5.5 installer for the same architecture at the computer's own keyboard and screen. It upgrades in place and keeps rules, settings and the password. While the service restarts, connections to other computers are blocked, usually for under a minute, and open connections drop; blocks in that window show as "Blocked" in Network Activity and are not prompted. Do not restart or power off the PC while setup runs. If a step fails, setup rolls back to the installed version; [In-place upgrade](https://github.com/ryanportfolio/SecureWall/blob/v0.5.5/docs/SECURITY.md#in-place-upgrade) has the recovery steps.

**Upgrading from v0.4.2 or older.** These versions cannot be upgraded in place. Uninstall SecureWall in Settings > Apps once, then install v0.5.5, following the one-time uninstall steps in the [v0.5.0 release notes](https://github.com/ryanportfolio/SecureWall/blob/v0.5.5/docs/releases/v0.5.0.md#downloads-and-installation).

**Switching from TinyWall.** Follow [before switching](https://github.com/ryanportfolio/SecureWall/blob/v0.5.5/docs/LIVE-TESTING.md#before-switching) first. Uninstall TinyWall with its own uninstaller and reboot before installing SecureWall; setup refuses to run while TinyWall or its firewall provider is still registered. To go back to TinyWall later, uninstall SecureWall first and follow [rolling back to TinyWall](https://github.com/ryanportfolio/SecureWall/blob/v0.5.5/docs/LIVE-TESTING.md#rolling-back-to-tinywall).

## Collect a diagnostic report

Read [the live testing guide](https://github.com/ryanportfolio/SecureWall/blob/v0.5.5/docs/LIVE-TESTING.md) and [coverage map](https://github.com/ryanportfolio/SecureWall/blob/v0.5.5/docs/DIAGNOSTIC-COVERAGE.md). Download the source archive for this tag to obtain `tools/diagnostics`, or use a checkout of this tag. Run the collector with Windows PowerShell 5.1 as described in [its README](https://github.com/ryanportfolio/SecureWall/blob/v0.5.5/tools/diagnostics/README.md). It creates a local report and does not upload it.

Logs record software outcomes and observed filtering decisions. They do not prove packet delivery, absence of boot/crash leakage, installer rollback, hostile filesystem resistance or power-loss durability. The bundled blocklists do not automatically update. Review normal-use logs before drawing conclusions about live behavior.
