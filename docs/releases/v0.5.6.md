# SecureWall v0.5.6

Website: https://secwall.org/

This is an unsigned alpha prerelease. A program whose file is also run by Windows services, such as Google Updater, can now be allowed from the blocked-connection popup, and a disabled Allow button now looks disabled.

## Changes

### Blocked-connection popup

- **Programs that share their file with Windows services can be allowed.** Since v0.5.4, a program whose executable is also the file of a Windows service got a prompt titled "Shared Windows service host" with Allow unavailable, even when the blocked process ran no service. Google Updater's `updater.exe` is one example. The popup now shows such a program by name, adds "(program and Windows services)", and names every service registered to run the same file. Allow outgoing saves the usual outgoing-only rule for that exact path, and that rule also lets those services connect; the notice and the button's tooltip say so. Always allow is not offered for these programs, so each copy in a new folder, such as each Google Updater version, asks again.
- **Some programs still cannot be allowed from the popup.** Allow stays unavailable when the process runs more than one service, for `svchost.exe`, for programs in the Windows folder such as `dllhost.exe`, when SecureWall cannot list every service that runs the file, and when it could not match the blocked connection to a process that is still running. The notice now says what to do instead: add a rule in Manage, Application Exceptions, for the one service when the program is `svchost.exe`, or for the program otherwise. A rule for the program also covers the services that run the same file.
- **A disabled button looks disabled.** Allow outgoing and Always allow kept their blue colour while unavailable, so a click that did nothing looked like a failure. They now turn grey while unavailable, including the moment after the popup appears before they accept clicks.

## Downloads and installation

Use `SecureWall_x64.msi` on Intel/AMD 64-bit Windows, `SecureWall_arm64.msi` on Windows on ARM, or `SecureWall_x86.msi` on 32-bit Windows. Verify the download against `SHA256SUMS.txt`. All installers are unsigned. Keep local console access and recovery installers available offline. Service loss can leave external networking blocked, including DNS and DHCP.

**Upgrading from v0.5.2 through v0.5.5.** Choose **Check for updates** in the tray menu or on the Maintenance tab in Manage, then **Install**.

**Upgrading from v0.5.0 through v0.5.5 by hand.** Run the v0.5.6 installer for the same architecture at the computer's own keyboard and screen. It upgrades in place and keeps rules, settings and the password. While the service restarts, connections to other computers are blocked, usually for under a minute, and open connections drop; blocks in that window show as "Blocked" in Network Activity and are not prompted. Do not restart or power off the PC while setup runs. If a step fails, setup rolls back to the installed version; [In-place upgrade](https://github.com/ryanportfolio/SecureWall/blob/v0.5.6/docs/SECURITY.md#in-place-upgrade) has the recovery steps.

**Upgrading from v0.4.2 or older.** These versions cannot be upgraded in place. Uninstall SecureWall in Settings > Apps once, then install v0.5.6, following the one-time uninstall steps in the [v0.5.0 release notes](https://github.com/ryanportfolio/SecureWall/blob/v0.5.6/docs/releases/v0.5.0.md#downloads-and-installation).

**Switching from TinyWall.** Follow [before switching](https://github.com/ryanportfolio/SecureWall/blob/v0.5.6/docs/LIVE-TESTING.md#before-switching) first. Uninstall TinyWall with its own uninstaller and reboot before installing SecureWall; setup refuses to run while TinyWall or its firewall provider is still registered. To go back to TinyWall later, uninstall SecureWall first and follow [rolling back to TinyWall](https://github.com/ryanportfolio/SecureWall/blob/v0.5.6/docs/LIVE-TESTING.md#rolling-back-to-tinywall).

## Collect a diagnostic report

Read [the live testing guide](https://github.com/ryanportfolio/SecureWall/blob/v0.5.6/docs/LIVE-TESTING.md) and [coverage map](https://github.com/ryanportfolio/SecureWall/blob/v0.5.6/docs/DIAGNOSTIC-COVERAGE.md). Download the source archive for this tag to obtain `tools/diagnostics`, or use a checkout of this tag. Run the collector with Windows PowerShell 5.1 as described in [its README](https://github.com/ryanportfolio/SecureWall/blob/v0.5.6/tools/diagnostics/README.md). It creates a local report and does not upload it.

Logs record software outcomes and observed filtering decisions. They do not prove packet delivery, absence of boot/crash leakage, installer rollback, hostile filesystem resistance or power-loss durability. The bundled blocklists do not automatically update. Review normal-use logs before drawing conclusions about live behavior.
